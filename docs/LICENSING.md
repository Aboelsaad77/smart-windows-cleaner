# Smart Windows Cleaner — Licensing & Entitlements Specification (Stage 3)

## 1. Overview & Core Philosophy

Smart Windows Cleaner employs an asymmetric, cryptographically verifiable licensing architecture designed to enforce clean entitlements without ever compromising system safety.

### Absolute Safety Boundary Invariant
```
+-------------------------------------------------------------------------+
|                         CORE CLEANING SAFETY ENGINE                     |
|                                                                         |
|  - NeverDelete Protection (WinSxS, Active Drivers, Running Executables)  |
|  - 13 Windows Core Safety Semantics & Pre-Flight Locks                 |
|  - Risk Engine Scoring (0-100) & Attribution Engine                      |
|  - Deterministic SHA-256 Quarantine Vault, Audit DB, & Safe Restore      |
|                                                                         |
|            ALWAYS 100% FREE, ACTIVE, AND UNTOUCHED ON ALL PLANS          |
+-------------------------------------------------------------------------+
                                    |
                                    | Strictly Isolated (Zero Influence)
                                    v
+-------------------------------------------------------------------------+
|                  NON-SAFETY ENTITLEMENTS (VALUE-ADD ONLY)               |
|                                                                         |
|  - pro.deep_forensics: Deep disk/registry forensics & telemetry export  |
|  - pro.scheduled_scans: Automated background task schedule triggers     |
|  - pro.advanced_reporting: Executive compliance / PDF/HTML audit reports|
+-------------------------------------------------------------------------+
```

**Cardinal Rule**: Licensing **NEVER** controls, modifies, bypasses, weakens, or influences:
1. SafetyEngine verdicts (`auto_quarantine`, `user_confirm`, `never_delete`).
2. WinSxS component store protection or driver protection.
3. In-use file locking or path traversal prevention.
4. Quarantine, restore, or retention purge operations.

Every user on Community Edition receives the exact same safety protection and core cleanup capability as an Enterprise deployment.

## 2. Signed Entitlement Envelope Schema

Licensing envelopes are distributed as JSON documents or base64-encoded strings:

```json
{
  "schema_version": "1.0.0",
  "license_id": "lic_2026_09a8bc4e",
  "account_id": "acc_enterprise_9182",
  "account_email": "ops@enterprise.org",
  "plan": "pro",
  "entitlements": [
    "pro.deep_forensics",
    "pro.scheduled_scans",
    "pro.advanced_reporting"
  ],
  "device_id": "8f480329a1b24e68e4a8b7921a8d05e27a92019485b0284e9182374619a82e91",
  "issued_at": "2026-09-18T12:00:00Z",
  "expires_at": "2027-09-18T12:00:00Z",
  "grace_until": "2027-10-02T12:00:00Z",
  "seq": 104,
  "kid": "smartcleaner-license-2026-1",
  "signature": "V291bGQgeW91IGxpa2UgdG8gc2VlIGEgbGl2ZSBzaWduYXR1cmUgZXhhbXBsZT8="
}
```

### Schema Attributes

| Field | Type | Description |
|---|---|---|
| `schema_version` | String | Must equal `"1.0.0"`. |
| `license_id` | String | Unique license identifier generated by issuer. |
| `account_id` | String | Subscriber or enterprise organization ID. |
| `account_email` | String | Licensee contact email address for display in Settings. |
| `plan` | String | `'community' \| 'pro' \| 'enterprise'`. |
| `entitlements` | Array of Strings | Permitted capability identifiers (`pro.deep_forensics`, etc.). |
| `device_id` | String | Bound device identifier (SHA-256 fingerprint) or `*` for volume seats. |
| `issued_at` | String (ISO 8601) | Timestamp of issuance. |
| `expires_at` | String (ISO 8601) | Expiration timestamp. |
| `grace_until` | String (ISO 8601) | Hard end of offline grace period. |
| `seq` | Number | Strictly monotonic sequence number per account for replay protection. |
| `kid` | String | Pinned public key identifier used for verification. |
| `signature` | String (Base64) | Ed25519 signature over canonical payload. |

## 3. Cryptographic Verification & Canonicalization

1. **RFC 8785 (JSON Canonicalization Scheme - JCS) Compliance**:
   - The signable payload consists of all fields in the envelope excluding `signature`.
   - Keys are sorted strictly by UTF-16 code units.
   - Negative zero (`-0`) is serialized as `0`.
   - `undefined`, functions, and symbols are omitted.
   - Zero superfluous whitespace tokens.
2. **Ed25519 Digital Signature**:
   - Verification executed via Node.js `crypto.verify(null, dataBuffer, pubKeyObj, signatureBuffer)`.
   - Signature failure immediately rejects envelope (`LIC_INVALID_SIGNATURE`).
3. **Client Binary Pinned Keys**:
   - Desktop binaries contain **public keys only**.
   - Private signing keys are held strictly in HSM / offline air-gapped signing infrastructure.

---

## 4. Hardware Device Binding

- Hardware fingerprints are calculated non-reversibly using:
  `SHA-256("smartcleaner:v1:" + platform + ":" + arch + ":" + cpuModel + ":" + cpuCount + ":" + memGiB + ":" + hostname)`
- Total RAM is rounded to nearest GiB to tolerate virtualization ballooning.
- Enterprise volume seats support wildcard `device_id: "*"`.

---

## 5. Replay Protection & Monotonic Ratchet

- Each envelope incorporates an integer `seq`.
- The local license store records `lastSeenSeq` per account.
- Any envelope where `seq <= lastSeenSeq` is rejected with `LIC_REPLAY_ATTACK_DETECTED`.

---

## 6. Offline Grace Period & Clock Rollback Detection

1. **Offline Grace Policy**:
   - The application does not contact a license server on startup.
   - If `now <= expires_at`: Status is `Active` (`is_active = true, is_in_grace_period = false`).
   - If `expires_at < now <= grace_until`: Status is `In Grace Period` (`is_active = true, is_in_grace_period = true`). Pro entitlements continue uninterrupted while prompting the user to renew.
   - If `now > grace_until`: Status drops cleanly to `Community Edition` (`is_active = false`).
2. **Clock Rollback Detector**:
   - Stores `lastVerifiedTimestamp` in the local store.
   - If `currentSystemTime < lastVerifiedTimestamp - 3600_000` (1-hour NTP drift tolerance):
     - `clock_rollback_detected = true`.
     - Pro entitlements are paused until time resynchronizes.
     - Core cleaning and SafetyEngine remain 100% operational.

## 7. RFC 8628 Device Authorization Flow

For seamless, passwordless activation:
```
Desktop Client                                  Web Browser / Server
      |                                                  |
      |-- 1. startDeviceAuth() ------------------------->|
      |<-- Returns { user_code: "WDNR-8492", uri } ------|
      |                                                  |
  [Displays user_code & link to user]                    |
      |                                        User visits verification_uri
      |                                        Enters "WDNR-8492" and confirms
      |-- 2. pollDeviceAuth(device_code) --------------->|
      |<-- Returns authorized signed license envelope ---|
      |                                                  |
  [Verifies Ed25519, saves to disk, unlocks Pro]
```

## 8. Feature Gating Abstraction

Applications query:
```typescript
if (isEntitled("pro.deep_forensics")) {
  renderForensicsViewer();
}
```
If not entitled, the UI provides non-intrusive upgrade prompts in Settings without altering scanning performance.
